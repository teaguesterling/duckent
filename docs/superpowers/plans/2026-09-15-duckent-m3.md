# duckent M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the O layer honest and cheap, make R0°/R1/R2 defaults so a plain table is the degenerate tree, and close every defect the duck_block_utils and panduck reviews found, all as macros on DuckDB 1.5.5.

**Architecture:** `_pre` becomes the rank of ORDER within ROOT, the size derivation becomes a level-expanded ASOF join, and O conformance, ORDER, level and key checks run at ingest in the same statement lists as P13. Every compiled query and traversal reads one `__proj` CTE plus a `__sib` window CTE, so no fragment keeps a range `NOT EXISTS`. The harness is tightened first, so every later kill and test result can be trusted.

**Tech Stack:** DuckDB 1.5.5 (Python package), SQL macros, Python 3 test harness, sitting_duck (community extension) for the css lowering and the live differential, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-15-duckent-m3-design.md` (read it in full; it wins over this plan where they differ). Background: `docs/superpowers/specs/2026-09-13-duckent-core-design.md`, `docs/superpowers/specs/2026-09-14-duckent-m2-design.md`, `FINDINGS.md`.

## Global Constraints

- DuckDB 1.5.5 exactly (`pip install duckdb==1.5.5`); sitting_duck from the community repository; Python 3.12+.
- Inside a macro body, struct fields are read with parentheses `(x).f`; lambdas are `lambda x: …`.
- A subquery or aggregate inside a lambda-bearing expression is refused after macro inlining: carry values through one-row CTE columns.
- `recurring.<cte>` may appear only in FROM position of a `USING KEY` recursive term, never inside a correlated subquery.
- `query()` accepts text only from macros whose own body contains no SELECT or subquery: `tree_compile_projection` and every `tree_sql_*` fragment stay pure string expressions.
- `CREATE OR REPLACE MACRO` with a different arity drops the other overload: never reuse a macro name with a new arity; rename instead.
- `error(NULL)` returns NULL instead of raising: every refusal goes through `tree_err(msg)` / `tree_css_err(msg)`, and every identity concatenated into a message is `COALESCE`d.
- Generated SQL text that refuses at run time calls `tree_err(...)` too (the macro exists in the session that runs it).
- Every compiler returns a statement list that fails closed: an optional statement is NULL by construction; a required one going NULL is refused, never filtered away.
- Copy-and-edit mutants are generated by `python3 test/mutants/regen.py`; after changing any macro a mutant copies, run it, then `python3 test/mutants/regen.py --check`.
- The corpus importer `python3 test/import_astcss_eval.py` is idempotent: a second run leaves `git status --porcelain` clean.
- Before every commit: `python3 test/run.py test/sql` (all PASS, none skipped), `python3 test/test_css_parser.py`, `python3 test/run_mutants.py` (ends with every kill verified), and paste their tails in the task report.
- Implementation-vs-tests golden rule: a new record is shown failing before its fix (paste the RED output); an existing expectation changes only as a stated consequence of the task, named in the commit message.

```python
def error_message(e):
    """DuckDB's message without the SQL it echoes back ("\nLINE 1: ..."), so an expected error
    can only match what the error SAYS, never the statement that raised it."""
    return str(e).split("\nLINE ")[0]


def run_file(path, mutant=None):
    lines = open(path).read().split("\n")
    sess = None
    failures = []
    asserted = 0          # query records and `statement error` records executed
    seen_record = False
    for header, body, expected, lineno in parse_records(lines):
        words = header.split()
        if words[0] == "require":
            if seen_record:
                failures.append((lineno, "require must come before the first record", header))
                continue
            probe = duckdb.connect()
            try:
                probe.execute(f"LOAD {words[1]}")
            except Exception:
                if os.environ.get("DUCKENT_NO_SKIP") == "1":
                    print(f"FAIL {path}: SKIP refused under DUCKENT_NO_SKIP (require {words[1]})")
                    return [(lineno, "skipped under DUCKENT_NO_SKIP", header)]
                print(f"SKIP {path} (require {words[1]})"); return []
            continue
        seen_record = True
        if sess is None:
            sess = Session(mutant)
        kind = words[0]
        try:
            if kind == "statement":
                want_error = words[1] == "error"
                if want_error:
                    asserted += 1
                try:
                    sess.execute(body)
                    if want_error:
                        failures.append((lineno, "expected error, statement succeeded", body))
                except Exception as e:
                    msg = error_message(e)
                    if not want_error:
                        failures.append((lineno, f"unexpected error: {e}", body))
                    elif expected and not any(exp.strip() in msg for exp in expected):
                        failures.append((lineno, f"error text mismatch\n    got: {msg}\n    want: {expected}", body))
            elif kind == "query":
                asserted += 1
                cur = sess.execute(body)
                rows = [[fmt(v) for v in r] for r in cur.fetchall()]
                if "rowsort" in words: rows.sort()
                got = ["\t".join(r) for r in rows]
                if got != expected:
                    failures.append((lineno, f"result mismatch\n    got:  {got}\n    want: {expected}", body))
            else:
                failures.append((lineno, f"unknown directive {header}", body))
        except Exception as e:
            failures.append((lineno, f"runner error: {e}", body))
    if asserted == 0:
        failures.append((0, "the file asserts nothing (no query and no statement error record ran)", path))
    for lineno, msg, body in failures:
        print(f"FAIL {path}:{lineno}: {msg}\n    sql: {body[:300]}")
    print(("PASS " if not failures else "FAIL ") + path)
    return failures
```

def suite_result(test, overlay, env):
    """'pass', 'fail' (exit 1 with at least one FAIL record) or 'broken' (the overlay did not
    load, or the suite failed without a FAIL record). Memoized on the overlay's path."""
    key = (test, overlay, tuple(sorted((k, v) for k, v in env.items() if k.startswith("DUCKENT_"))))
    if key not in _cache:
        r = subprocess.run([sys.executable, os.path.join(ROOT, "test/run.py"), os.path.join(ROOT, test),
                            "--mutant", overlay], capture_output=True, text=True, env=env, cwd=ROOT)
        if r.returncode == 0:
            _cache[key] = "pass"
        elif r.returncode == 1 and any(l.startswith("FAIL ") and ".test:" in l for l in r.stdout.splitlines()):
            _cache[key] = "fail"
        else:
            _cache[key] = "broken"
    return _cache[key]
